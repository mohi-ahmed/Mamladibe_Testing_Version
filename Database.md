### 1.1 Authority order

1. `API_CONTRACT.md` controls endpoint paths, public payloads, enum strings, HTTP statuses and error codes.
2. The SRS controls product behavior, security and acceptance requirements.
3. This document controls MongoDB collections, fields, indexes and persistence rules.
4. `Architecture.md` controls component boundaries and request flows.

Internal fields may differ from public DTOs only through an explicit service mapper. MongoDB `_id`, `actorId`, network hashes, credential hashes and moderation internals must never leak into public responses.

### 1.2 Current repository state

- The frontend exists and currently uses seeded data plus `localStorage` as a demo store.
- `API_CONTRACT.md` defines the replacement integration boundary.
- No production database connection or backend model is created by this document update.
- The downloaded earlier database document remains an external historical copy.

## 2. Database principles

- Public users have no accounts.
- A random HttpOnly browser cookie is converted server-side into a pseudonymous `actorId`.
- `actorId` identifies a browser installation, not a person.
- Raw IP addresses and raw anonymous-cookie tokens are never persisted.
- Reporter Secrets are generated by the backend. Only a secure hash is persisted.
- Support, Dispute, flag and visible-comment counts are calculated, not stored on incidents.
- Unique indexes enforce one vote per actor per incident and one flag per actor per target.
- Flag or vote totals never trigger automatic content removal.
- Moderation actions require a reason and append an immutable audit record.
- Locations are stored as GeoJSON `[longitude, latitude]`; the API returns flat `lat` and `lng`.
- Dates are BSON `Date` values in UTC.
- Bangla and English strings are trimmed and Unicode NFC-normalized.

## 6. Collection schemas

### 6.1 `incidents`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `_id` | ObjectId | auto | Internal only |
| `trackingId` | String | Y | Unique public identifier; exact length remains coordinated |
| `secretHash` | String | C | Required for public reports; excluded from default queries |
| `title` | String | Y | Trimmed, 5-100 |
| `description` | String | Y | Trimmed, 20-2,000 |
| `category` | Enum | Y | One canonical category |
| `incidentAt` | Date | Y | Not later than server time |
| `location` | GeoJSON Point | Y | `[lng, lat]`, inside Bangladesh |
| `roadName` | String | N | Plain text |
| `areaName` | String | Y | Plain text; manual fallback allowed |
| `safetyTip` | String | N | Maximum 500 |
| `status` | Enum | Y | Default `published` |
| `actorId` | String | C | Required for public reports; internal only |
| `source` | Enum | Y | `public` or `admin` |
| `contentHash` | String | Y | Duplicate-detection hash; internal |
| `isEdited` | Boolean | Y | Default false |
| `editedAt` | Date | N | Latest text edit |
| `byModerator` | Boolean | Y | Default false |
| `createdAt` | Date | Y | Server time |
| `updatedAt` | Date | Y | Mongoose timestamp |
| `hiddenAt` | Date | N | Moderation timestamp |
| `deletedAt` | Date | N | Soft-delete timestamp |
| `purgeAt` | Date | N | Used only after retention approval |

Public mapping flattens the location, calculates counts and adds `viewerState`. It never exposes `_id`, `secretHash`, `actorId` or `contentHash`.

Indexes:

- Unique `{ trackingId: 1 }`.
- `{ location: "2dsphere" }`.
- `{ status: 1, createdAt: -1 }`.
- `{ status: 1, category: 1, createdAt: -1 }`.
- `{ actorId: 1, createdAt: -1 }`.
- Text index on `title`, `description`, `roadName`, `areaName`.
- Optional TTL on `purgeAt` only after retention approval.

### 6.2 `incident_versions`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `incidentId` | ObjectId | Y | Incident reference |
| `version` | Integer | Y | Starts at 1 for first prior snapshot |
| `title` | String | Y | Prior value |
| `description` | String | Y | Prior value |
| `safetyTip` | String | N | Prior value |
| `savedAt` | Date | Y | Server time |
| `editedBy` | Enum | Y | `reporter` or `moderator` |
| `adminId` | ObjectId | C | Moderator edit |
| `reason` | String | C | Moderator edit |

Unique index: `{ incidentId: 1, version: 1 }`.

Before an edit, the service saves the prior text. Reporter edits use a 15-minute server-time window and the contract's combined-string Levenshtein ratio, rejecting values above `0.20`.

### 6.3 `comments`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `_id` | ObjectId | auto | Public opaque comment `id` |
| `incidentId` | ObjectId | Y | Incident reference |
| `actorId` | String | Y | Internal author |
| `type` | Enum | Y | `correction`, `extra`, `opinion` |
| `text` | String | Y | Plain text, 5-500, links rejected |
| `status` | Enum | Y | Default `published` |
| `createdAt` | Date | Y | Server time |
| `hiddenAt` | Date | N | Moderation timestamp |
| `deletedAt` | Date | N | Author/admin soft-delete |
| `purgeAt` | Date | N | After retention approval only |

Indexes:

- `{ incidentId: 1, status: 1, createdAt: -1 }` for newest-first, ten-per-page lists.
- `{ actorId: 1, createdAt: -1 }` for ownership, quota verification and activity.
- Optional TTL on `purgeAt` after retention approval.

The API derives `mine`, `canDelete` and `hasFlagged`; raw `actorId` is not returned.

### 6.4 `votes`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `incidentId` | ObjectId | Y | Incident reference |
| `actorId` | String | Y | Internal browser actor |
| `type` | Enum | Y | `support` or `dispute` |
| `createdAt` | Date | Y | Server time |
| `updatedAt` | Date | Y | Vote switch time |

Unique index: `{ incidentId: 1, actorId: 1 }`. Switching updates the row; undo removes it. Counts never determine truth or moderation state.

### 6.5 `reports`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `targetType` | Enum | Y | `incident` or `comment` |
| `targetId` | ObjectId | Y | Target reference |
| `actorId` | String | Y | Internal flagger |
| `reason` | String | Y | Target-specific enum |
| `reviewStatus` | Enum | Y | Default `pending` |
| `outcome` | Enum | N | `kept`, `hidden`, `removed` |
| `note` | String | N | Admin review note |
| `reviewedBy` | ObjectId | N | Admin |
| `reviewedAt` | Date | N | Review time |
| `createdAt` | Date | Y | Server time |

Indexes:

- Unique `{ targetType: 1, targetId: 1, actorId: 1 }`.
- `{ reviewStatus: 1, createdAt: 1 }`.
- `{ targetType: 1, targetId: 1 }`.

Incident and comment reasons use a discriminated validation schema.

### 6.6 `actors`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `actorId` | String | Y | Unique HMAC-derived identifier |
| `firstSeenAt` | Date | Y | First public write |
| `lastSeenAt` | Date | Y | Throttled update |
| `createdAt` | Date | Y | Server time |

The raw `mdb_anon` value is never stored. Admin responses use a safe prefix and activity, not a raw token or real-world identity.

### 6.7 `rate_events`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `actorId` | String | N | Actor event |
| `networkHash` | String | N | HMAC-derived; never raw IP |
| `action` | Enum | Y | `incident`, `comment`, `vote`, `flag`, `track`, `admin_login` |
| `result` | Enum | Y | `allowed`, `limited`, `captcha_required`, `blocked` |
| `createdAt` | Date | Y | Server time |
| `expiresAt` | Date | Y | Short-lived TTL |

Indexes: actor/action/time, network/action/time and TTL `expiresAt`.

Redis is authoritative for rolling counters. Comment submission atomically removes events older than 24 hours, counts the remaining events and rejects a sixth event. The oldest remaining event plus 24 hours becomes `resetsAt`.

### 6.8 `blocks`

| Field | Type | Req | Rules |
|---|---|---:|---|
| `targetType` | Enum | Y | `anonymous_id` or `network_hash` |
| `targetHash` | String | Y | Internal only |
| `mode` | Enum | Y | `temporary` or `permanent` |
| `reason` | String | Y | Required admin reason |
| `expiresAt` | Date | C | Temporary block |
| `active` | Boolean | Y | Default true |
| `createdBy` | ObjectId | Y | Admin |
| `createdAt` | Date | Y | Server time |
| `removedBy` | ObjectId | N | Admin |
| `removedAt` | Date | N | Removal time |

Index: `{ targetType: 1, targetHash: 1, active: 1 }`. Network-hash and permanent blocks require Super Admin. Removal deactivates the row instead of deleting history.

### 6.9 `geo_cache`

Fields: unique `key`, optional `roadName`, optional `areaName`, `provider`, `createdAt`, `expiresAt`. Use a unique key index and TTL expiry.

Provider failure does not block reporting when coordinates are valid. The frontend can enter a road/area manually.

### 6.10 `admin_users`

Fields: unique lowercase `email`, `passwordHash`, `role`, encrypted `totpSecretEncrypted`, `active`, `failedLogins`, optional `lockedUntil`, optional `lastLoginAt`, timestamps.

Passwords use Argon2id or another explicitly approved strong one-way hash. TOTP secrets use authenticated encryption.

### 6.11 `admin_sessions`

Fields: `adminId`, unique `sessionHash`, `csrfHash`, `createdAt`, `lastSeenAt`, `expiresAt`. Use a TTL index on `expiresAt`.

The cookie contains the raw random token and is HttpOnly, Secure and SameSite=Strict. Only the hash is stored.

### 6.12 `audit_logs`

Fields: `adminId`, controlled `action`, `targetType`, safe `targetId`, required `reason`, optional small `before`/`after` summaries and `createdAt`.

Indexes: admin/time, target/time and created time. No update or delete operation exists. Summaries exclude secrets, hashes, tokens and full sensitive bodies. Retention remains deferred.

## 7. Integrity and concurrency

### 7.1 One-action constraints

- Vote: unique `(incidentId, actorId)`.
- Flag: unique `(targetType, targetId, actorId)`.
- Incident: unique `trackingId`.
- Admin: unique lowercase `email`.
- Session: unique `sessionHash`.

Duplicate-key errors map to contract errors such as `DUPLICATE_FLAG` or `CONFLICT`; raw database errors are never returned.

### 7.2 Multi-write flows

| Flow | Required behavior |
|---|---|
| Comment | Reserve rolling quota in Redis, then insert comment; monitor insert failures |
| Quick edit | Save prior version, then conditionally update within server-time window |
| Moderation | Content change plus audit entry should be atomic where supported |
| Permanent delete | Super Admin only; audited, idempotent dependent cleanup |

### 7.3 Soft deletion

Normal admin deletion sets `status=deleted` and `deletedAt`. Public APIs return the same `NOT_FOUND` result for unknown, hidden and deleted content. Permanent deletion is Super Admin only.

Purge timing and legal-hold behavior remain deferred. No content TTL is enabled until approved.

| Rule | Enforcement |
|---|---|
| Title 5-100 | Strict API schema, service, Mongoose |
| Description 20-2,000 | Strict API schema, service, Mongoose |
| Safety tip max 500 | Strict API schema, service, Mongoose |

| Incident time not future | Service using server clock |

| GeoJSON order `[lng, lat]` | Mapper and schema |

| Quick edit 15 minutes | Conditional update using `createdAt` |
| Quick edit ratio <= 0.20 | Combined-string Levenshtein service rule |
| Tracking credentials | Constant-time hash comparison |
| Admin authorization | Session, role and CSRF middleware |
| Unknown JSON fields | Strict request schema |

## 9. API mapping responsibilities

- `location.coordinates[1]` becomes `lat`; index 0 becomes `lng`.
- Incident counts are returned as flat `support`, `dispute`, `flags`, `commentCount`.
- `viewerState` is derived from the current actor.
- Comment `mine`, `canDelete`, `hasFlagged` are derived from the actor.
- Tracking responses contain versions/edit availability, never `secretHash`.
- Admin activity uses a safe actor prefix; public responses contain no actor identifier.

## 10. Security and privacy

- Anonymous cookie: `mdb_anon`, HttpOnly, Secure, SameSite=Lax, Path=/.
- Cookie lifetime remains coordinated; do not restore the old `mdb_actor` name.
- Actor and network identifiers are HMAC-derived.
- Raw browser tokens and raw IP addresses are never stored.
- Reporter Secrets are hashed and compared in constant time.
- Sensitive Mongoose fields use `select: false` and explicit projections.
- Backups are sensitive and require encryption and restricted access.

## 11. Setup and migrations

- Disable automatic production index creation during serverless cold starts.
- Use an explicit idempotent setup command during controlled deployment.
- The setup command never drops collections or data automatically.
- Migrations are versioned, reviewed, idempotent and tested outside production.
- Enum changes require coordinated contract, frontend and backend updates.

## 13. Implementation checklist

- [ ] Public enums exactly match section 5 and `API_CONTRACT.md`.
- [ ] Public incidents use `trackingId`; MongoDB incident `_id` is hidden.
- [ ] Comments store `text`, not the older `body`.
- [ ] Comments return ten per page, newest first.
- [ ] Comment quota is rolling 24 hours, not an Asia/Dhaka calendar day.
- [ ] Quick edit is 15 minutes with a combined 20 percent limit.
- [ ] Backend generates Tracking ID and Secret; Secret is returned once.
- [ ] `mdb_anon` and raw IP values are never stored.
- [ ] Incident/comment flag reasons are validated separately.
- [ ] Unique vote and flag indexes exist before launch.
- [ ] Moderation writes an append-only audit entry with a reason.
- [ ] Error mapping follows `API_CONTRACT.md`.
- [ ] Tests cover constraints, GeoJSON order, quota races, edit races and secret exclusion.

## 14. Deferred decisions

- Exact Tracking ID and Secret length/grouping.
- Anonymous cookie lifetime.
- Numeric rate limits other than five comments per rolling 24 hours.
- Admin session idle/absolute duration.
- Retention, purge and legal-hold policy.
- Geocoding provider and cache lifetime.
- Final Bangla full-text search strategy.
- Mandatory transaction policy for moderation plus audit.

None may change a public endpoint, enum, payload field, error code or pagination shape without revising `API_CONTRACT.md` and integration tests in the same change.
